# RiftboundGym

A rules-accurate simulator for the Riftbound TCG, built as an RL environment. The end goal is to
train PPO agents to pilot meta decks, measure matchup win rates between decks, and serve the agents
as practice opponents in the browser sim. See README.md for the roadmap. The rules engine is still
incomplete: there is no movement, combat or card abilities yet, so games are decided by Burn Out.

## Commands

```bash
python3 -m pytest                 # tests (pytest-style functions in test_*.py; pip install pytest if missing)
python3 game.py                   # 200 headless random-vs-random games
python3 sim.py [--agent mod:Cls]  # browser sim on :8765 (also the "riftbound-sim" config in .claude/launch.json)
```

## Architecture

- `cards.py`: `CardDef` is the *printed* card: immutable, shared by every copy. Never put mutable
  game state on it.
- `zones.py`: `CardInstance` holds per-object state (damage, exhausted, controller, zone). Moving
  between non-board zones makes a new object (`become_new_object`, rule 124).
- `game.py`: `Game` owns all state. External code interacts only through the decision loop:
  `acting_player`, `legal_actions(seat)`, `step(action)`, `observation(seat)`. Keep that contract
  stable, since the sim and future RL wrappers depend on it.
  - `step` must reject anything not in `legal_actions`.
  - `observation(seat)` must be JSON-serializable and must never leak hidden information (opponent
    hand, deck order, face-down runes). Tests check this. Treat a leak as a bug, because it lets
    agents cheat.
  - Use `self.rng` for all randomness so games stay reproducible from `seed`. `Game` must remain
    deep-copyable and picklable (used for search/rollouts).
- `step` runs everything that needs no decision, including passing priority or ending the turn
  when that is a player's only option, so `acting_player` always faces a real choice.
- Spells are only playable once their card_id has an entry in `SPELL_EFFECTS`; unimplemented
  cards must stay unplayable rather than resolve with no effect. Tests register dummy cards there.
- Legal actions are deduplicated: copies of a card in the same zone give one action, and payment
  options (`Game.payment_options`) differ only in what they leave behind (ready runes, recycled
  domains, legend use). Keep it that way; every extra action makes PPO's job harder.
- Agents implement the `Agent` protocol: a `name` attribute and `act(observation, legal) -> Action`.

## Rules source

`Riftbound-Core-Rules-RUP4-July-16-2026.pdf` is the authority. When implementing or changing a rule,
look it up there rather than relying on memory of the game, and follow the existing style of citing
the rule number in a trailing comment (`# 485.3`). If the rules are ambiguous, ask instead of
guessing.

## Workflow

- **Tests with every change**: any change to game logic, cards, zones or deck loading adds or
  updates tests in `test_*.py`. Run the full suite before calling a change done.
- **Branches + PRs**: never commit directly to `main`. Create a branch, then open a PR against
  `main` (the repo is shared with a collaborator).
- Card data in `card_data/` is generated by `import_sheet.py`. Fix gaps via its `OVERRIDES` rather
  than hand-editing the JSON.
